# croupier

An opencode plugin that installs an orchestrated, slice-by-slice frontend
workflow driven by specialist subagents. Write a feature spec with a
`## Slices` section, run `/croupier`, and an orchestrator agent plans one
slice at a time, runs it through a deterministic verify loop, reviews it,
and stops at a human gate before the next slice.

The plugin injects everything the workflow needs into your opencode config —
agents, the `/croupier` command, the `croupier-workflow` skill and a
`chrome-devtools` MCP server — without overwriting anything you already have:
your own `agent`, `command`, `skills` and `mcp` settings win over plugin
defaults. It also registers two deterministic tools (`croupier_verify`,
`croupier_visual_diff`) that replace the old `scripts/*.mjs` harness.

## Requirements

- Node `>= 20` (see `.nvmrc`).
- opencode 0.4 or newer.

## Install

Add the package to the `plugin` array of your opencode config
(`~/.config/opencode/opencode.json` for a global install, or your project's
`opencode.json`):

```json
{
  "plugin": ["@yabbadabbadev/croupier"]
}
```

**Restart opencode** after installing or editing the config — the plugin
injects on startup, there is no hot reload. On restart it registers:

- the agents `croupier-orchestrator`, `croupier-planner`,
  `croupier-test-writer`, `croupier-implementer`, `croupier-reviewer` and
  `croupier-visual-reporter`;
- the `/croupier` command and the `croupier-workflow` skill;
- the tools `croupier_verify` and `croupier_visual_diff`;
- a `chrome-devtools` MCP server (only if you don't define one yourself).

## Usage

1. Write the feature spec in `docs/superpowers/specs/` with a `## Slices`
   section (see `docs/croupier-workflow.md` for the workflow reference).
2. Run `/croupier` in opencode. The orchestrator picks the active slice
   (from `progress.md`) and follows the workflow: plan, red tests, green
   implementation, `croupier_verify` gate, review, visual report.
3. Review the slice result and answer at the gate to continue.

## Model parameterization

No agent pins a `model`: subagents inherit the orchestrator's model and the
orchestrator inherits the global one. To fix models per agent, add them to
your opencode config (global or project):

```json
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "croupier-orchestrator": { "model": "openrouter/deepseek/deepseek-v4.1" },
    "croupier-implementer": { "model": "{env:CROUPIER_IMPL_MODEL}" }
  }
}
```

`{env:VAR}` and `{file:...}` values are supported. Restart opencode after the
change.

## The tools

- `croupier_verify` — runs `tsc --noEmit` and `vitest run --reporter=json`
  in the project directory and returns a structured JSON result
  (`passed`, `typeCheckPassed`, `unitTestsPassed`, `output`,
  `failedTestNames`).
- `croupier_visual_diff` — compares two PNGs (`before`, `after`) with
  `pixelmatch` and returns the ratio and count of differing pixels;
  optionally writes the diff image to `diff`.

Both run relative to the project directory (the git worktree opencode is
running in).

## Development

```bash
pnpm install
pnpm test            # vitest run
pnpm run typecheck   # tsc --noEmit
pnpm run build       # tsup -> dist/
pnpm run lint        # oxlint
pnpm run format      # prettier --write .
pnpm run format:check
```

Linting is **oxlint**, formatting is **prettier** — ESlint is intentionally
not part of this project.

## Publishing

Releases flow from **merging the release PR**: `release-please` keeps a
release PR on `main` carrying the version bump and the CHANGELOG entry, and
merging it creates the tag and triggers the `publish` job in
`.github/workflows/release.yml`. Publishing uses **npm trusted publishing
(OIDC)** — no `NODE_AUTH_TOKEN` is stored anywhere.

One-time manual setup (done once, from any machine):

1. On **npmjs.com**, register a trusted publisher for
   `@yabbadabbadev/croupier` with the four exact values: organization
   `yabbadabbadev`, repository `croupier`, workflow filename `release.yml`,
   environment `npm-publish`. All four fields are case-sensitive.
2. Create the **`npm-publish` GitHub environment** on this repository,
   **with a required reviewer configured on it**. The workflow waits for
   that reviewer before running `npm publish` — this is the human gate that
   trusted publishing does not remove. If the environment does not exist,
   GitHub auto-creates it unprotected and the publish proceeds with no gate.
3. Enable Settings → Actions → General → "Allow GitHub Actions to create and
   approve pull requests", or release-please cannot open the release PR.

Commits on `main` must follow
[Conventional Commits](https://www.conventionalcommits.org/): `feat:` and
`fix:` commits produce a release PR; `docs:`, `ci:`, `chore:` and `refactor:`
do not. `CHANGELOG.md` is generated by release-please.

See `docs/croupier-workflow.md` for workflow details and the manual
acceptance checklist.
